# Runbook: 계측 통신 두절(Communication Loss) 대응 절차

- 단계: 수집
- 적용 설비: gw-01 및 게이트웨이에 연결된 모든 계측 설비
- 적용: 계측 게이트웨이(RTU)가 특정 설비의 데이터를 일정 시간 이상 받지 못하거나 결측률이 높을 때
- 증상 예시: 계측값이 갱신되지 않음, 통신이 끊김, 모니터링 화면 값이 멈춤, 수신 오류
- 기준(가정): 5분 이상 미수신 주의, 15분 이상 경보 / 결측률 5% 이상 주의

> 상황 절은 위에서부터 키워드를 확인합니다. 위험한 상황일수록 위에 두세요.

## 기본 절차
1. get_equipment_status로 게이트웨이의 마지막 수신 경과 시간, 결측률, 연결 설비 수를 확인한다.
2. 응답이 없는 설비의 통신 경로(Modbus RTU 배선, 국번 주소, Zigbee 신호 세기)를 점검한다.
3. 두절된 설비의 계측값은 경과 시간과 함께 표시하고, 15분 이상 지난 값은 판단 근거에서 제외한다.
4. 게이트웨이 통신 모듈을 재연결하고, 복구 후 결측 구간을 보고서에 남긴다.
5. 같은 설비에서 반복되면 통신 장비 교체나 이중화 작업을 등록한다.

## 상황 1: 게이트웨이 전체가 두절됨 (모든 설비 값이 멈춤)
- 키워드: 모든 설비, 전부 안 들어, 전체가 안 들어, 게이트웨이 전원, 게이트웨이가 꺼
- 증상 예시: 모든 설비 값이 한꺼번에 멈춤, 모니터링 화면 전체가 갱신 안 됨, 게이트웨이 응답 없음
- 판단 근거: 게이트웨이 자체의 마지막 수신이 15분 이상 지남(가정), 연결 설비 전체 미수신
- 대응: 아래 절차(기본 절차 대신)
1. 게이트웨이 전원, LAN 링크 표시등, 상위 서버와의 네트워크 연결을 확인한다.
2. 복구 전까지 모든 설비의 계측값을 판단 근거에서 제외하고, EMS 자동 제어를 일시 중지한다(운영자 승인 필요).
3. 게이트웨이를 원격 재기동한다(운영자 승인 필요).
4. 재기동으로 복구되지 않으면 현장 순회 점검으로 ESS·변압기 등 안전 설비 상태를 직접 확인한다.

## 상황 2: 특정 설비 하나만 두절됨
- 증상 예시: 한 설비만 값이 멈춤, EV 충전기만 데이터가 안 들어옴, 특정 설비 응답 없음
- 판단 근거: 해당 설비만 15분 이상 미수신(가정), 다른 설비는 정상 수신
- 대응: 기본 절차와 동일

## 상황 3: 끊겼다 이어졌다를 반복 (결측률만 높음)
- 키워드: 간헐, 끊겼다, 들쭉날쭉, 결측률
- 증상 예시: 데이터가 간헐적으로 비어 있음, 값이 들어왔다 안 들어왔다 함, 결측률이 높게 나옴
- 판단 근거: 결측률 5% 이상(가정)이지만 완전 두절은 아님
- 대응: 기본 절차 + 아래 추가 조치
1. 무선 구간이면 신호 세기와 주변 간섭원(인버터 노이즈 등)을 확인한다.
2. 폴링 주기와 타임아웃 설정이 설비 응답 속도에 맞는지 점검한다.
3. 배선 접촉 불량이 의심되면 단자 체결 상태를 현장 점검한다.

## 상황 4: 값은 들어오지만 같은 값으로 고정되거나 시간이 맞지 않음
- 키워드: 같은 값, 값이 고정, 시간이 안 맞, 타임스탬프
- 증상 예시: 값이 몇 시간째 똑같음, 계측 시각이 실제 시각과 다름, 값은 오는데 변하지 않음
- 판단 근거: 30분 이상 값 변화 없음(가정) 또는 계측 시각 오차 5분 이상(가정)
- 대응: 아래 절차(기본 절차 대신)
1. 고정된 값은 판단 근거에서 제외하고, 해당 설비 계측기의 동작 상태를 확인한다.
2. 게이트웨이와 계측기의 시간 동기화(NTP) 설정을 점검한다.
3. 계측기 교체나 재설정이 필요하면 작업을 등록하고 그동안 현장 확인 값으로 대체한다.
